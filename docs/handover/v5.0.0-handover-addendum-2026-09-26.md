# Addendum — 2026-09-26 — corrections to `v5.0.0-handover.md`

The handover (commit `d5be5a7`, measured at `bff6cc4`) was sent for independent verification in the `sol-codex` lane before its approval was recorded. **It came back BLOCK with nine findings — four HIGH.** The base document is not revised; these corrections supersede it where they conflict.

**The reviewer was right on every finding I re-checked, and three of them I verified against the repository myself before writing this.** Two change conclusions in the base document, and one of those *reduces* the release risk I claimed.

---

## Corrections that change a conclusion

### C1 — The installed-exposure argument in §19 was FALSE (was R1-F7, MEDIUM; I rate it higher)

§19 said teammates installing from `main` would receive `.claude/test-cmd` narrowing their Stop gate, and would run the `kyj5` litter-producing L1 test. **None of that reaches a target.** Verified against the shipped manifest:

```
grep -c 'test-cmd' manifests/v5.0.0.sha256              -> 0
grep -c '\.claude/scripts/tests/' manifests/v5.0.0.sha256 -> 0
grep -c 'impact-report.test.sh' manifests/v5.0.0.sha256   -> 0
```

`.claude/test-cmd` is untracked and absent from the manifest; `.claude/scripts/tests/` is repository-only.

**Consequence:** `.claude/test-cmd` and `kyj5` are **repository-maintainer hygiene defects, not installed-user exposure.** The base document overstated the cost of releasing now. The recommendation direction survives — the reviewer independently adjudicated it as still supported — but two of the three reasons §19 gave for urgency were wrong about who is affected.

### C2 — §15 item 4 was FALSE (was R1-F2, HIGH)

The base document claimed that at HEAD "every L2 spec **skips** on `BD_SHIM_ONLY=1`" and that L2 gives "near-zero signal". Measured at run `36232214628`:

```
Specs:  Total: 48  Passed: 32  Failed: 1  Skipped: 15  Partial: 4
```

with 2,353 passing assertions. **32 of 48 specs pass; 15 skip.** L2 gives substantial signal.

This was a false statement inside the section whose entire purpose is listing false statements — the worst place to put one, because readers trust that section most. I generalised from a log excerpt showing consecutive skips to "every spec", without counting.

## Net effect on the decision

**The recommendation does not change: refine briefly, then release.**

What changes is the *weight*:

- **Lower** than the base document implied: `.claude/test-cmd` and `kyj5` do not reach installed users (C1); L2 is not signal-free (C2).
- **Unchanged and still decisive:** the tag names the worse tree; CI has never been green; `qnvo` (P0) may make task-per-unit approve uncompletable; **no evidence v5 has run on any real product repository** — and per C10 below, that is an unknown, not a disproof.
- **Newly uncertain:** every backlog figure (C4, C5).

### C10 — §15 item 8 overreached (was R1-F6, MEDIUM)

"The plugin has been used on real work" was listed as *false*. Absence of evidence in an audit that explicitly did not perform the install check (§13) does not establish falsity. The correct statement: **this audit does not establish real-world use, in either direction.**

## Method note

This addendum exists because the handover was sent for independent verification instead of taking the `--no-review` bypass the QA gate offered. Nine findings, four HIGH, two changing conclusions — in a document I had already checked, and which already disclosed two self-caught measurement errors.

The lesson generalises past this artifact: **self-caught errors in a document are not evidence that the remaining figures are sound.** I caught two by reconciling against stated totals; the reviewer caught nine more by re-running the commands against the repository. Those are different activities, and only the second is verification.
