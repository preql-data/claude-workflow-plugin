## 3. What was cut, and why

**U5 — staging e2e QA: CANCELLED.** Four reasons, ranked: most external dependencies of any phase; largest security surface, since injected auth means credentials in a harness the plugin drives unattended; the only phase requiring live paid runs, so its evidence would have been the weakest in a release whose standing rule is *no adjective without an artifact*; and the provider abstraction is speculative until a **second** project validates the shape — building from one project's needs would encode that project's assumptions as the interface.

**Not deferred on a timer. There is no date at which this becomes correct.** It becomes correct when a second project needs staging QA, which is also the evidence that would tell us what to build.

**U3 — reduced to a contract field.** The motivating problem (a 14-PR speculative-fix chain) is already solved by evidence-before-fix, which is shipped and working. Building a ledger to detect a class of failure another mechanism already prevents is surface without a defect to justify it. The harness design is preserved in full on `gio.1`, **deferred behind an evidence bar**: name three closed tasks whose `context_coverage` omitted the same class of source. Evidence first, machinery second.

**U4 — reduced to one vendored reference doc** plus a practice harvest, rather than five registered skills.

**U6 — CLOSED need-triggered; the 2026-08-23 date is RETIRED.** Depth-1 is not a limitation awaiting removal — **it is an enforcement mechanism.** Because subagents cannot spawn subagents, an implementer *structurally cannot procure its own review*; grader and reviewer spawns must originate at the root, which is precisely the separation the gate's independence predicate guarantees. Raising the pin would mean writing a parent-role guard to restore in software what the platform gives for free, to enable nesting no workflow here needs. Standing task `1bn` states the trigger as a **condition, not a date** — the platform default has moved three times in this project's lifetime, so a calendar check would have fired against whichever value happened to be current and told us nothing.

## 6. The CI break, and the process gap that caused it

`manifests/v4.1.0.sha256` was written by shell redirection, so `post-edit.sh` never saw it and **it never entered a change-set hash** — a new file reached a release commit without any reviewer's change set naming it. C5's reviewer then scoped its re-run by grepping for readers of the two *edited* files.

**Both decisions were locally reasonable. Together they let a regression reach a tag.**

There is a sharper edge than "nobody grepped the new file": `install.sh:1317` reads it by **constructed** name (`manifests/v$V3_DETECTED_VERSION.sha256`), so a literal grep for `v4.1.0.sha256` would have found nothing anyway. **The check that would have caught this is "who globs or constructs paths under `manifests/`", not "who names this file."**

The fix was also larger than the four red assertions, for a reason worth recording: because both table sources now describe the same release, the subject/control pair **stopped discriminating on outcome** — it differed only in which table got *named*. Correcting the assertions alone would have left the section weaker than before *while showing green*. Proven by mutation: stripping the manifest-preference makes the naming assertions fail **while the count assertions stay green**.

## 7. The release's meta-finding

The plugin gates itself, so its own signals are load-bearing. This release found **six ways they claimed more confidence than their evidence supported**:

| ID | Finding |
|---|---|
| `qzv` | F1 stamps `qa-approved` on a task whose work does not exist, closes it, and clears `current-task`. **Fired on the release task itself**, 22 s after the implementer spawned, bound to a *previous* task's change set. |
| `94d` | The change-set tracker under-covers, so an approval can bind a smaller set than the diff. |
| `1nz` | Live-repo assertions fail under any concurrent writer — **five instances**, the last being the Stop hook racing the gate's own state machine. |
| `2ty` | The J21 counter charges a thorough review against the defect budget, and auto-defers. |
| `hbr` | An advisory CI job is permanently red — indistinguishable from newly-broken. |
| `A10` | A frozen audit row was false when written, not stale. |

Each reads as a nit alone. Together they are one finding, now recorded in `LESSONS.md`:

> **A gate that reports confidently on unverified evidence is worse than no gate, because it is trusted.**

**The containment is the good news, and it is real.** When `qzv` fired on the release task, v4's change-set binding meant the Stop hook would emit `LABEL_WITHOUT_RECORD` and re-block rather than release on the stale label — and `plugin.json` is reviewable source under F1's own classifier, so it could not re-fire. **v3 would have released on this; v4 did not.** The damage was to the record, not the release.

It was caught only because `bd_update_task` echoed back `status=closed, labels=[qa-approved]` when the implementer had passed neither. **Specialists re-reading task state at completion would have caught all four instances** — cheap, and worth adopting.
