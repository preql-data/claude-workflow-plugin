# Lessons ledger

Production lessons learned the hard way. Each entry is a single-sentence
takeaway, traceable to the Beads task(s) that produced it, with the date
it was first recorded.

Add new entries via `.claude/scripts/lessons.sh add '<lesson>' --source <task-id>`
— never hand-edit. The helper deduplicates by normalized text (case- and
whitespace-insensitive), so repeating an existing lesson appends the new
source to that entry rather than creating a duplicate. The only legitimate
hand-edit is pruning entries that are no longer relevant.

The orchestrator reads this file during planning (see `orchestrator.md`),
the grader (Phase A) receives it in the grading packet, and the QA agent
proposes additions at epic close. Treat it as the institutional memory the
plugin runs against, not a static reference doc.

## Lessons

- Parallel agents in the same working tree contaminate each other's branches; concurrent specialists require worktree isolation. <!-- sources: claude-workflow-plugin-e0d.7 --> <!-- recorded: 2026-06-11 -->
- Boundary mocks must use the real downstream producer's shape, pinned via a fixture extracted from the producer's spec — never invented. A mock that feeds `body.error` so the test can assert `body.error` is circular and proves nothing. <!-- sources: claude-workflow-plugin-e0d.7 --> <!-- recorded: 2026-06-11 -->
- New agent files must be registered in .claude-plugin/plugin.json agents[] in the same commit that creates them; an unregistered agent is silently invisible to the SDK — no error surfaces. Guard: agents-manifest-parity test. <!-- sources: claude-workflow-plugin-l1r.5 --> <!-- recorded: 2026-06-11 -->
- Subagents cannot spawn other subagents in the Claude Code runtime (docs: sub-agents page — Agent(agent_type) has no effect in subagent definitions). Any agent-spawning step must live at the root conversation level; design multi-agent handoffs as root-orchestrated relays, never nested spawns. <!-- sources: claude-workflow-plugin-l1r.5 --> <!-- recorded: 2026-06-11 -->
- Interface examples must be executed by a test: the Makefile's own usage string (make test-live FIXTURE=node-react-auth) was broken for the one fixture whose spec file is scenario-named — nothing ever ran the documented invocation. Caught only when a paid live run failed fast. Any CLI surface a doc or help text advertises needs an L2 assertion that executes that exact invocation (dry-run mode where the real one costs money). <!-- sources: claude-workflow-plugin-366.4 --> <!-- recorded: 2026-06-11 -->
- Prose cues do not reliably drive subagent tool usage: across 4 live runs, QA made zero impact_of calls even when its task prompt contained the exact tool name, alias, target symbols, and invariant name. When a workflow REQUIRES a tool call, make it mechanical (compute it where calls are reliable — e.g. orchestrator at root — and pass results down), don't prompt for it. <!-- sources: claude-workflow-plugin-n6d --> <!-- recorded: 2026-06-12 -->
- Rendered fixture installs pin plugin scripts at render time: the fixture's verify-before-stop.sh predated the cue fix by one commit, so a hook-template change never reached the live run. Script-level fixes require re-rendering fixture installs (or a version check at run start) before they affect live validation. <!-- sources: claude-workflow-plugin-366.10 --> <!-- recorded: 2026-06-12 -->
- Never run QA review concurrently with a builder in the same working tree: QA attributed the parallel C.2 task's freshly-written files to the C.1 task under review and blocked it for scope creep. Sequence QA after all writers finish, or give builders worktree isolation (orchestrator.md 4b exists for exactly this). <!-- sources: claude-workflow-plugin-n45.1 --> <!-- recorded: 2026-06-12 -->
- Manifest-declared assets must be presence-asserted at the install target: install.sh's hardcoded agent list silently dropped grader.md for two releases (v3.2.0-v3.3.0) — every fresh install was missing the rubric loop's grader while the repo's own tests stayed green. Glob-copy from the manifest source of truth and add an installer-spec presence assertion for every plugin.json agents[]/commands[] entry. <!-- sources: claude-workflow-plugin-n45.4 --> <!-- recorded: 2026-06-12 -->
- Bash functions invoked via $(...) command substitution run in a subshell — any variable they set is lost to the parent. The manual-adopt gate in model-select.sh was dead code for exactly this reason (set at :341, read at :500, never connected). When a helper must signal the caller, encode the signal in its stdout contract (e.g. a MANUAL<tab> prefix) and parse it at every call site; add a META-TEST that strips the parse to prove the gate is load-bearing. <!-- sources: claude-workflow-plugin-3fn --> <!-- recorded: 2026-06-12 -->
- A security hardening that breaks the workflow is worse than the documented residual it closes. Fail-closing prevent-orchestrator-edits.sh on ambiguous identity assumed every specialist carries a probeable identity, but this runtime does not surface subagent_name to PreToolUse hooks — so it denied legitimate specialist Write/Edit (a P0-class regression) to close a P2 Bash-write vector. When a guard depends on an identity signal the runtime may not provide, prefer fail-OPEN plus the structural guard (the orchestrator's omitted Write/Edit tools, which IS airtight) and document the residual; never trade a P2 for a P0. <!-- sources: claude-workflow-plugin-llh.19 --> <!-- recorded: 2026-06-13 -->
- Line-number-anchored mutation META-tests are brittle: any comment or line addition above the anchor silently un-lands the NR==<n>/sed -n Np target, turning a load-bearing META into a no-op (or a spurious failure). Anchor mutation METAs to a unique TEXT pattern in the target line, not an absolute line number. (3 instances re-anchored across verify-before-stop/escalation-binding specs this session.) <!-- sources: claude-workflow-plugin-llh.20 --> <!-- recorded: 2026-06-13 -->
- Effort A/B (cnz.2): verdict max — ultracode showed ZERO orchestration interference in a 39-min time-boxed arm (no Workflow-layer engagement, all spawns on-list, plugin flow faithful), contradicting the pre-registered criterion-4-failure expectation; max still wins because ultracode pins the model at its xhigh proxy (below max) with no observed benefit, and criteria 2-3 went unverified under the time-box. <!-- sources: claude-workflow-plugin-cnz.2 --> <!-- recorded: 2026-07-25 -->
- Paid-run cost estimates must be derived from measured token flows, not guessed: the EFFORT-AB-TEST runbook estimated $10-20 for both arms; actual was ~$206 API-equivalent (~$169 arm B full + ~$37 arm A time-boxed) — a 10x error that forced a mid-test re-confirmation gate. <!-- sources: claude-workflow-plugin-cnz.2 --> <!-- recorded: 2026-07-25 -->
- Regional/transient model exclusions in .claude/model-ranking go stale silently: a `!family` line added for a temporary outage keeps masking downstream behavior (here it collapsed the v4 top==opus-class role split onto Opus for six weeks) long after the outage clears. Gate every un-exclusion on FRESH spawn evidence (subagent-spawns.log + effort-ab logs naming the model), not memory, and date the rationale + rollback line in the file. <!-- sources: claude-workflow-plugin-bi3.2 --> <!-- recorded: 2026-07-25 -->
- Files rewritten by a helper (awk/mv, e.g. workflow-model-apply.sh) instead of the Edit/Write tool never land in changed-files.txt, so the QA impact hash and the change-set-bound approval only cover Edit-tracked files. When a task mutates files via a helper, QA must verify those files explicitly via git diff (not rely on the impact report alone). <!-- sources: claude-workflow-plugin-bi3.2 --> <!-- recorded: 2026-07-25 -->
- MCP registration scope is a mechanical contract, not etiquette: a detection probe reads ONE config path (top-level .mcpServers of ~/.claude.json for user scope), so local/project-scope registrations are silently invisible — verify the probe read path when writing setup docs and make wrong-scope the first troubleshooting row. <!-- sources: claude-workflow-plugin-1vq.2 --> <!-- recorded: 2026-07-25 -->
- Published CLI config references can lag the shipped binary: verify accepted values against the binary own introspection surface (e.g. codex debug models) rather than the docs or trial-and-error, and record the lag in the operator doc so editors re-verify. <!-- sources: claude-workflow-plugin-1vq.2 --> <!-- recorded: 2026-07-25 -->
- Run suites via their canonical make targets: a bare runner invocation (npx vitest run) includes guarded paid live specs whose fail-closed API-key errors masquerade as regressions; the CI-shaped target (make test-e2e-unit) is the comparable baseline. <!-- sources: claude-workflow-plugin-1vq.2 --> <!-- recorded: 2026-07-25 -->
- When a change adds a second independent gate to a release path, every META that isolates the FIRST gate must be re-seeded to satisfy the new gate so it still fails for its own reason (jio.1 MM18 migration is the template). <!-- sources: claude-workflow-plugin-jio.1 --> <!-- recorded: 2026-07-26 -->
- A deliberate second implementation of a gate predicate (shell counter + TS live invariant) is only a second witness if QA diffs the two rule-by-rule against the writer grammars at their emit sites — the jio.2 parity review caught a greedy-sed vs first-match token-selection divergence (gqp) that every test suite had missed. <!-- sources: claude-workflow-plugin-jio.2 --> <!-- recorded: 2026-07-26 -->
- Trace-anchor refreshes that add a skip must be legitimized against the on-disk cassette (jq has(field) on the replay file), not the spec comment — and the pin must assert skipped+pass+exact detail so a future re-record flips loud instead of silently inheriting the skip. <!-- sources: claude-workflow-plugin-jio.2 --> <!-- recorded: 2026-07-26 -->
- State a gate writes for its own bookkeeping can destroy the evidence a later check needs: qa-gate.sh approve truncates changed-files.txt, so re-running impact-report.sh --hash-only in the approving checkout returns the empty-list hash and can never reproduce the approved hash — even there. Any cross-checkout or after-the-fact verification must read the PERSISTED record (impact-report-<tid>.json, which survives approve), never recompute; assert the destruction in the test so making it conditional fails loudly instead of silently disabling the reader. <!-- sources: claude-workflow-plugin-3mg.2 --> <!-- recorded: 2026-07-26 -->
- The two-file awk join idiom NR==FNR is true for every record of the SECOND file when the first file contributes zero records — an empty first input silently swallows the entire join; load the lookup file in BEGIN via getline and add a structural row-count self-check instead. <!-- sources: claude-workflow-plugin-gzc --> <!-- recorded: 2026-07-26 -->
- jq empty is not a merge-input validity oracle — it accepts empty files and multi-document streams; any jq -s merge that indexes .[0]/.[1] positionally must gate its inputs on "length == 1 and (.[0] | type == \"object\")" or the second document of a corrupted input silently binds as the other merge side. <!-- sources: claude-workflow-plugin-p5n --> <!-- recorded: 2026-07-26 -->
- Add-if-absent config clauses must key on presence (has("key")), never value truthiness — an operator-owned key holding an explicit null or false is still operator-owned, and truthiness guards silently clobber it on upgrade. <!-- sources: claude-workflow-plugin-p5n --> <!-- recorded: 2026-07-26 -->
- When a reviewer finding names one call site, sweep every sibling call site with the same shape before resolving — the p5n settings merge carried the identical positional-binding hole the finding named for .mcp.json, and the sweep (J27 step 6) is what made the resolution complete rather than symptomatic. <!-- sources: claude-workflow-plugin-p5n --> <!-- recorded: 2026-07-26 -->
- When adding a new rung to a detection ladder, probe every input class the EARLIER rungs already claim — an earlier detector can shadow the new rung for inputs its comment says it covers (v2 signal 2 vs detect_v3 signal (b) on deleted-manifest trees), leaving documented coverage dead on arrival. <!-- sources: claude-workflow-plugin-x15 --> <!-- recorded: 2026-07-27 -->
- install.sh run from outside a checkout-shaped directory silently clones the plugin source from the network — any A/B comparison of installer versions (probes, METAs, specs) must run each version from a local git-archive tree, never from an extracted single file. <!-- sources: claude-workflow-plugin-pnf --> <!-- recorded: 2026-07-27 -->
- An invariant that is only nearly true — a probe reporting "no file changes" while one file is written — is one a future change can break without failing a test. Count the write or delete the claim. <!-- sources: claude-workflow-plugin-56r --> <!-- recorded: 2026-07-27 -->
- A path-traversal guard written as a string test on the path is not a containment guard: [ -f ] and hashing both follow symlinks, so the only sound checks are physical containment of the resolved path, or refusing path shapes the producer never emits (e.g. root scope is flat by construction). <!-- sources: claude-workflow-plugin-56r --> <!-- recorded: 2026-07-27 -->
- A brace group composed with `{ ... } > file || fail-arm` must not end on a guarded command like `[ -n "$x" ] && printf` — the guard rc becomes the group rc on the empty case and fires the failure arm after every write succeeded; end such groups with an unconditional command (e.g. `:` or an always-true printf). <!-- sources: claude-workflow-plugin-n64 --> <!-- recorded: 2026-07-27 -->
- A BOM-less .ps1 is decoded as ANSI by Windows PowerShell 5.1, and non-ASCII bytes inside string literals can decode to smart quotes (U+201D/U+201E terminate double-quoted strings per the PS grammar) — keep PowerShell source ASCII outside whole-line comments, guard it mechanically, and compose any required non-ASCII output at runtime via [char]0xNNNN. <!-- sources: claude-workflow-plugin-m7e --> <!-- recorded: 2026-07-27 -->
- When a source literal must change encoding but its rendered output is byte-pinned to another implementation, compose the character at runtime and make the parity extractor resolve the composition — then guard both directions (a literal-reintroduction check AND a wrong-codepoint check) so neither the source property nor the output parity can silently regress. <!-- sources: claude-workflow-plugin-m7e --> <!-- recorded: 2026-07-27 -->
- When a change extends an installer copy surface into an operator-owned directory, every preservation leg must be extended in the same change — upgrade backup, update backup, fresh-path guard, and uninstall — and the regression test must assert the backup CONTAINS the replaced bytes, not that the report says so. <!-- sources: claude-workflow-plugin-36z --> <!-- recorded: 2026-07-27 -->
